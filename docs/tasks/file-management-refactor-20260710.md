# 文件管理页拆分与并发安全优化

## 结果

- 将 `FileManagement.vue` 从 2720 行收敛为 465 行的页面编排器。
- 新增文件管理展示组件目录，拆出头部、工具栏、双视图、分页、菜单、弹窗、预览、上传面板与通知。
- 将列表、文件操作、预览分享、上传队列、菜单和 Toast 状态收敛到独立 composable，删除未接入的面包屑 composable 及文件/上传占位 Store。
- 使用 `file:<id>` / `folder:<id>` 作为实体键，消除文件与文件夹数字 ID 冲突。
- 上传改为共享三 worker 队列，支持真实请求取消、失败重试、目录创建锁和销毁清理。
- 新增列表竞态、预览资源释放、CRUD、上传并发/取消、组件事件及页面集成测试；前端 13 个测试文件、91 个测试通过。
- 对低频网格视图、菜单和复杂弹窗按需加载，文件管理主路由产物由 66.54 kB 降至约 51.30 kB。

## 教训

- 已存在 composable 不代表拆分已完成；必须确认页面是否真正消费其返回状态，以及实现是否仍是占位逻辑。
- Vue 将普通对象放入响应式数组后，继续直接修改原始对象不会可靠触发 computed；异步队列应统一持有 reactive proxy 或采用不可变更新。
- 取消 UI 状态不等于取消副作用。上传、预览和目录浏览都需要 AbortController 与请求序列共同保护。
- 文件和文件夹来自独立表时，数字 ID 不能直接作为跨实体选择键或渲染 key。
- Vue SFC 的模板拆分仍需执行生产 build；typecheck 无法覆盖所有模板编译风险。

## 可沉淀模式

- 大型页面先建立行为测试，再按“纯类型/函数 → 展示组件 → 领域 composable → 页面接线”分阶段迁移。
- 页面只负责跨域编排；请求生命周期、资源释放和竞态保护由拥有该状态的 composable 负责。
- 并发队列使用单一 worker pool、任务级 AbortController 和 `Map<key, Promise<Result>>` 锁，避免每批各自限流及错误回退。
- 低频且体积较大的业务组件应在有构建数据支持时按需加载，而不是假设拆文件自然降低首屏包体。
